# 音声入り作品アーカイブの負荷測定

作品アーカイブの保存済み音声を、ブラウザのIndexedDBから読み、`.vaarchive`へ書き出し、破損検査を含めて読み込み、新しい作品IDで保存する処理を測る。音声エンジンは使わず、合成PCMを入力にする。

## 実行方法

Node.js 24で`npm ci`と`npx playwright install --only-shell chromium`を済ませ、ほかの重い処理を止めて実行する。

```sh
npm run benchmark:archive
```

専用のVite開発サーバーを`127.0.0.1:3213`で起動し、1ワーカーで18ケース（PC・モバイル表示×3条件×3回）を実行する。通常のE2Eには含めない。動作確認だけなら`npm run benchmark:archive -- --repeat-each=1`を使う。`.local-artifacts/archive-benchmark/<日時>/report.md`と`report.json`に集計・各反復・失敗を残す。生成物はGit対象外。

| 条件                                 | 合成WAVの合計 | 用途               |
| ------------------------------------ | ------------: | ------------------ |
| 2行×1秒 / 24kHz / 16bit / モノラル   |     約0.09MiB | 小さい作品         |
| 10行×10秒 / 48kHz / 16bit / モノラル |     約9.16MiB | 中程度の作品       |
| 20行×34秒 / 48kHz / 16bit / モノラル |    約62.26MiB | 1作品64MiB上限付近 |

各反復は新しいブラウザコンテキストで行い、実際のアーカイブ関数とIndexedDBを使う。`save-source-audio`は合成WAVの元作品への保存、`export`はIndexedDB読み出しからアーカイブ作成、`inspect`は形式・条件・WAVハッシュの検査、`restore`は別IDへのIndexedDB保存と作品設定の公開を測る。復元後に音声件数・総バイト数・作品IDを確認する。API通信は遮断する。計測前にモジュールを読み込む。2フレームの描画待ちを各区間へ含める。UIのクリック、ファイルのダウンロード転送、WAV合成時間は含まない。

モバイル条件はiPhone 13相当の表示・タッチ操作をChromiumで模擬し、ページCPUを4倍に減速する。物理iPhone・Safariの測定ではなく、IndexedDBやブラウザ内部処理に同じ減速がかかる保証もない。JSヒープは`performance.memory`の区間後の概算値で、Blobの実体・IndexedDB・ブラウザのネイティブメモリー・ピーク使用量を含まない。保存使用量は`navigator.storage.estimate()`の概算。`longestTaskMs`はページのPerformanceObserverが見た50ms以上のタスクで、暗号化・保存などの非同期処理の負荷を網羅しない。

## 2026-10-23の結果

macOS/arm64、Apple A18 Pro、8GiBメモリー、Node v24.14.1、Chromium 156.0.8078.4で18ケースすべて成功した。ソース編集中の測定で、記録のHEADは`ab5a6d8`、`dirty: true`。所要時間は各条件3回の中央値。ローカルの生データは`.local-artifacts/archive-benchmark/2026-10-23T08-50-21-434Z/report.json`にある。

| 表示・音声量           | 元音声保存 ms | 書き出し ms | 読み込み検査 ms | 復元 ms | 復元後の保存使用量概算 |
| ---------------------- | ------------: | ----------: | --------------: | ------: | ---------------------: |
| PC・0.09MiB            |          14.2 |        33.0 |            33.1 |    33.3 |                 0.3MiB |
| PC・9.16MiB            |          15.9 |        33.0 |            33.2 |    33.1 |                18.5MiB |

20行条件の最大観測JSヒープ概算は73.1MiB、50ms以上のページ内タスクは観測されなかった。元作品と復元作品の両方に音声が残るため、ブラウザの保存使用量概算は約124.8MiBとなり、全作品128MiB上限に近い。空き容量が少ない環境では復元が拒否され得る。

## 上限の判断

現行の1作品64MiB・全作品128MiB上限は維持する。今回のデスクトップChromiumでは上限付近のアーカイブ作成・検査・復元が完了したが、物理モバイル端末の総メモリーピークと容量不足時の挙動は測っていない。上限の引き上げやモバイルでの快適性判断には、低メモリー物理端末でのアプリ画面を通した測定が必要。
