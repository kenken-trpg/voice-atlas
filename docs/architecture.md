# 設計と初期版の範囲

## 体験

採用声ライブラリは`shared/voice-library.ts`で検証する専用の`voice-atlas-voice-library` v2（旧v1も読み込み可能）。UUIDの登録ID、キャラクター名、設定名、メモ、作成/更新日時、採用時の比較評価のコピーを保持する。A/B採用だけを比較評価から登録し、当時の調声値・理由・生成情報・任意のモデル情報を変更せず、名前とメモだけを編集する。履歴用スキーマを用いるため現行カタログから外れた記録も保存できる。候補へ読み込む際には現行の操作用スキーマで再検証する。

調整による別設定は任意の`variation`に候補・セリフ・生成情報・4軸/設定・変更理由と、派生元のID/名前/調声値/セリフの非再帰的なコピーを持つ。元の`evaluation`は初回採用時の記録として保持し、調整保存を新しい採用評価として作り直さない。`libraryCandidate`/`libraryText`/`libraryGeneration`/`libraryContext`は派生設定があればそちらを参照する。元の登録と派生元のコピーは編集・削除で変化せず、派生元がファイルに含まれなくても読み込める。同一話者・スタイルと生成情報の製品一致を検証し、自己参照を拒否する。v1では派生フィールドを拒否して、v2のデータを旧形式として黙って欠落させない。

`CastingWorkspace`は読み込んだ登録を話者キーごとの作業用コピーとして保持し、現在の音声キャッシュと元の設定のキャッシュを分ける。元の設定は読み込み時点のコピーで固定し、両音声を同じ共通セリフで順次生成する。共有のbusy/abort処理を使い、条件変更で古い音声を表示せず、音声の置き換え・復元・終了時にObject URLを解放する。1候補の生成が成功して現在の条件に一致すれば`VoiceVariationEditor`から保存できる。モデル情報はその音声の生成時に確認できたものだけを保存する。別設定は`VoiceLibrary`の同じ容量検証・localStorage書き込み経路を使って新IDで追加する。比較セッションJSON/履歴再開では作業用の派生元を解除し、誤った系譜を引き継がない。

`VoiceLibrary`は合計100件・UTF-8 JSON 4MiB以下を検証後、localStorageの`voice-atlas-voice-library-v1`へ書き込み、成功してから画面状態を更新する。容量不足や破損した保存データでは自動上書きしない。専用JSONの取り込みは既存登録への追加で、同一ID/同内容を除外し、同一ID/異なる内容や件数超過は全体を拒否する。ブラウザ内だけで処理し、サーバーへ送信しない。画像・APIキー・音声は保存しないが、名前・メモ・理由・作者の設定は保存される。

ライブラリから候補A/Bへ読み込む前に、製品・調声値・現行カタログ・反対側との同一候補衝突・200候補上限を検証する。指定した候補と共通セリフ・`comparisonContext`を更新し、ほかの設定と評価履歴は保持する。音声は破棄して再生成する。未導入AivisSpeechは保持でき、生成時に現エンジンへ再照合する。利用可否は現在の接続一覧から表示する。

画像を選択 → 声の演出案を作成 → カタログの候補を比較 → 調声値を編集 → 試聴 → レシピを保存。

VOICEVOXの2候補は共通セリフで順次生成して比較できる。調声値は話者・スタイルのカタログIDごとに保持し、試聴音声はIDとセリフ・調声値の組み合わせで照合する。設定が異なる古い音声は表示しない。生成済み音声は候補ごとに最大1件をブラウザー内に保持し、置き換え・作業のリセット・画面終了時にObject URLを解放する。

比較評価は、日時・4軸・共通セリフ・2候補の調声値・結果・理由の独立したスナップショットとして最大100件を保持する。後の調整で過去の条件を書き換えない。A/Bの採用を記録すると保存対象の声も変更する。

`shared/saved-recipe.ts` は保存JSONのv1/v2/v3を検証する。v2以降は選択中の声に加えて各候補の設定、比較対象、評価履歴、絞り込み条件を持つ。新規保存はv3とし、各評価に任意の`evidence`を保持する。旧履歴が混在していても、評価時の情報を補完しない。復元前に数値範囲とカタログID・スタイルを検証し、全体が有効な場合だけ画面状態を置き換える。取り込んだURL・ガイド・クレジットは表示に使わず、現在のカタログとガイドを利用する。JSONの読み込みはブラウザー内で完結し、音声・画像・APIキーは保存形式に含めない。

手動モードは画像を解析したように見せず、ユーザーが指定した4軸のみを使います。AI解析では視覚上の要素・演出提案・4軸をJSONで取得し、ユーザーがその4軸を修正できます。写真から実際の声や本人の属性を特定する設計にはしません。

## 保存した設定の比較

`shared/library-comparison.ts`は登録IDが異なる2つの`VoiceLibraryEntry`の組を検証し、同じ話者・スタイルの設定違いを許可する。通常の製品比較が話者キーで調整を共有するのに対し、`LibraryComparison`は各登録ID・共通セリフ・話者・調声値をキーとして音声を独立して保持する。比較開始時に2登録をコピーし、登録の編集・削除から切り離す。再生成の前には現行カタログと現在の利用可否を確認する。履歴の読み込み自体には現行カタログの存在を要求しない。

専用JSONは`voice-atlas-library-comparison` v1。現在の2登録/セリフ/使用場面/選択ID/理由と、最大100件の記録を持つ。各記録は独立ID・記録日時・2登録の完全なコピー・使用する登録IDと理由・セリフ・使用場面・今回の両試聴の生成情報と任意のモデル情報を保存する。選択IDの所属、同一登録同士の比較禁止、記録IDの重複、製品/話者と生成情報の対応を検証する。モデル情報を登録時から流用しない。記録とJSON読み込みの際に8MiBのUTF-8上限を検証してlocalStorageの`voice-atlas-library-comparisons-v1`へ書き込み、成功後だけ画面状態を反映する。音声・画像・APIキーは保存しない。ブラウザ再読み込みでは最後に記録/復元した状態を戻し、音声を再生成する。

生成は既存の`/api/casting/preview`へ製品固有の設定を送り、A/Bを順次処理する。片方成功後の再試行は成功した音声を再利用し、個別再生成はキャッシュを使わない。セリフ変更で過去の音声を表示せず、比較の切り替え/復元/終了時にObject URLを解放する。生成中は親の`CastingWorkspace`もロックして同時生成を防ぎ、比較画面やライブラリを閉じると待機を中止する。元の比較作業や登録を操作せず、履歴再開はこの比較欄だけを置き換える。履歴は25件ずつ表示し、JSONは常に全件を保存する。同じ製品の調声差だけを計算し、製品が違う場合は意味の違う項目を換算せずそれぞれの名前と値を表示する。

## 評価履歴の集計

`shared/evaluation-dataset.ts`は、レシピv2/v3の履歴抽出、評価JSON v1/v2の検証、重複除去、評価時・現行スコアの関係の集計、CSV出力を担当する。新規の評価JSONは`{format: "voice-atlas-evaluations", version: 2, createdAt, records}`で、各recordは評価スナップショットと取り込み元のカタログ確認日の集合を持つ。未知のカタログIDも歴史的記録として保持し、現在のスコアがないことを表示する。声の設定の復元とは異なり、カタログIDの現在の存在を取り込み条件にしない。

重複の照合には評価日時（UTCに正規化）・4軸・セリフ・順序付き候補と各調声値・結果・理由・任意の`characterInput`・任意の`evidence`全体を用いる。エンジン情報の確認日時もUTCに正規化する。評価時の版や取得したエンジン情報が異なるもの、旧記録と情報付き記録は別記録として保持し、情報を上書き・統合しない。同じ記録の確認日は集合として統合する。複数ファイルはすべて検証してから追加し、不正な入力や上限超過時に部分的な追加を行わない。最大1000件、一回20ファイル、各32MiB、合計64MiBまで。1件に統合するカタログ確認日は最大100個。

`EvaluationWorkbench`は声の設定と独立したメモリー状態を持ち、非表示時も保持する。現在の比較記録は利用者が明示的に追加する。25件ずつ表示し、JSON保存は全体、CSV保存は絞り込み条件に合う全体を対象にする。CSVはUTF-8 BOM、CRLF、引用符によるエスケープ、テキストセルの数式解釈防止を行う。

現行スコアは保存された4軸に現行の`recommend`を適用して算出する。評価時スコアと順位は`evidence`に保存した数値をそのまま表示し、当時の版に合わせて再計算しない。両者を別々に集計・絞り込みでき、版別の件数と版フィルターを持つ。CSVには評価時・現行の各スコア・順位・版情報、スコア差、A/Bそれぞれのエンジン情報を出力する。旧記録は「記録なし」、現行カタログの未収録候補は現行値を空欄にする。調声後の音響品質を測定したものとして扱わない。スコアが同点の候補はID順による順位差を一致・不一致に換算しない。同程度・判断不可は採用候補のスコア高低から除外する。集計から推薦式・カタログの値を自動変更しない。

## キャラクター設定の入力

`POST /api/analyze`は`inputMode`（`image`または`text`、省略時`image`）と`characterText`（2000文字まで、省略時空文字）を受ける。画像モードは画像が必須、テキストモードは空白以外の設定が必須で、`image`を含む要求を拒否する。テキストモードでは画像のデコード処理を通さず、Ollamaの`images`、OpenAIの`input_image`、Claudeの`image`、Geminiの`inlineData`を送信しない。既存の設定モデル・構造化出力と応答検証を共有する。OpenAIのテキスト入力は[official OpenAI documentation](https://developers.openai.com/api/docs/guides/text)に沿ってResponses APIを使う。Ollamaの`/api/show`では画像対応の`ready`と、ローカルの`completion`または`vision`対応を示す`textReady`を区別する。

プロンプトは作者の設定を創作上の意図として優先し、画像モードの`cues`は視覚的な要素、テキストモードの`cues`は作者が明記した設定の要約とする。テキストモードでは画像を見たような説明をしない。設定内の命令で出力形式や上位のルールを変更させない。UIの外部送信同意は送信内容を表示し、入力元・設定・補足・解析先の変更時に解除する。テストはモックのみで、有料APIを呼び出さない。

UIは編集中の入力と、現在の4軸に対応する`profileInput`を別々に保持する。手動検索・AIの成功時にだけ`profileInput`を更新し、文章の編集だけでは4軸・調声値・音声を変えない。差があれば再作成の案内を表示する。比較評価は`profileInput`を`characterInput`としてコピーし、後の編集と独立させる。レシピv3は任意の`characterInput`（編集中）と`profileInput`（適用済み・null可）を追加し、既存v1/v2/v3の読み込みを維持する。未知の画像・URL等はスキーマで除外し、旧記録に設定を補完しない。

レシピ読み込みは設定履歴100件を含められるよう4MiBまで、評価JSONは最大1000件の設定履歴を含められるよう1ファイル32MiB・一回64MiBまでとする。件数制限は据え置く。評価CSVには適用済みの入力モード・設定・演出の補足を追加し、テキストの数式解釈防止を適用する。集計の検索は設定・補足も含める。

## 評価時の推薦とエンジン情報

`shared/evaluation-evidence.ts`は評価確定時のスナップショットを作る。`algorithmRevision`、`catalogRevision`、カタログ確認日、`rankingScope: "voicevox-all"`、全候補数、A/Bの候補ID・スコア・順位、A/Bの音声に対応するエンジン情報を保持する。順位は利用可否・エンジン/予算フィルターを適用しないVOICEVOX全候補内の連番で、同点は既存の候補ID順とする。対応候補・スコア範囲・順位上限・順位重複・版文字列・日時を検証する。

推薦式の版は`shared/recommend.ts`の`recommendationRevision`、カタログの版は`shared/catalog.ts`の`catalogRevision`とする。スコア式・同点順・調声式の変更時は前者、話者・スタイル・プロフィール・調声方針の変更時は後者を更新する。一次資料の確認日は版番号と別に管理する。

`POST /api/preview`は音声生成に成功した後、同じ固定のローカルエンジンから任意で`GET /version`を取得する。[VOICEVOX公式のルーター実装](https://github.com/VOICEVOX/voicevox_engine/blob/master/voicevox_engine/app/routers/engine_info.py)にあるJSON文字列の応答を検証し、`{engine: "VOICEVOX", version, checkedAt}`をURIエンコードしたJSONとして`X-Voice-Atlas-Engine`ヘッダーへ付ける。追加取得は1秒・1024バイトまでとし、未対応・不正応答・通信失敗でもWAVを成功として返す。版情報の文字列は100文字まで、制御文字を禁止する。

ブラウザーは任意ヘッダーを検証して候補ごとの音声キャッシュに保持する。キャッシュされた音声を再利用する場合は、その音声に紐づく情報も再利用する。評価時の接続表示から版を流用しない。JSON復元後の過去の評価は変更せず、新たに生成した音声で評価すると新しい取得情報を記録する。エンジンの版は生成直後の取得値であり、コア・音声ライブラリの版や生成音声そのものを含む完全な再現条件ではない。

## 分担

- React/ViteのUIとExpressを同じローカルオリジンで提供。
- TypeScript/Zodでプロバイダー出力とユーザー入力を検証。
- AIは演出のプロフィールだけを提案し、ソフト・話者名を作りません。
- ソフト・話者は出典付き固定カタログから選択。カタログ以外の話者がAI出力から追加されることはありません。
- カタログは`CatalogSpeaker`（製品・話者名・規約・クレジット等）と`CatalogStyle`（スタイル名・4軸・調声方針・出典）を分けて保持し、既存APIと保存JSONには両者を結合した`Voice`を渡す。既存10候補のIDは維持する。公式情報の確認日と聴取評価の状態は別に記録し、未実施の評価日を作らない。
- 4軸のユークリッド距離で順位付けし、0〜100の編集上の目安として表示。確率・本人との一致率ではありません。
- VOICEVOXの提案値は控えめな範囲へ制限。ささやき等で音高を保持する提案は、表示名ではなくスタイルの`pitchPolicy`で指定する。利用者による音高の手動調整は可能。
- 話者IDはインストール済みエンジンの `/speakers` から解決し、`/audio_query` の値を上書きして `/synthesis` に渡す。
- COEIROINK・A.I.VOICE2にはソフト固有の数値が確認できるまで値を出さず、手動調整の方向と公式手順を示す。

## 製品横断の比較

`CastingWorkspace`は、導入済みVOICEVOX・AivisSpeechの比較を提供する。既存の推薦とVOICEVOXレシピv1/v2/v3の取り込みは維持し、未校正のAivisSpeechを固定カタログやスコア計算へ追加しない。独立したセリフ・候補別設定・音声キャッシュ・採用対象・評価履歴を持ち、閉じても作業状態を保持する。

`shared/casting.ts`の話者と調声値はそれぞれ製品で分岐し、両者の一致を検証する。VOICEVOXは既存カタログID・名前・スタイルを照合し、AivisSpeechはUUIDとスタイル名で識別する。数値スタイルIDは音声の生成情報としてのみ記録し、復元時の照合には利用しない。AivisSpeechの調声スキーマは`shared/aivis.ts`にあり、VOICEVOXの推薦値を流用しない。

`GET /api/casting/voices`は両エンジンを独立に確認する。片方の失敗を全体の失敗とせず、試聴可能な話者と確認時刻を返す。同じ話者/スタイルの重複やAivisSpeechの数値ID衝突は除外し、最大200候補を返す。未導入の保存候補は画面に残す。`POST /api/casting/preview`は製品別に検証した候補とセリフを受け取り、生成直後の任意のエンジン版を`X-Voice-Atlas-Generation`へURIエンコードJSONで返す。既存の解析・試聴と同じ排他制御を使う。接続先はサーバー設定のみから取得する。

保存形式は`{format: "voice-atlas-casting", version: 1, createdAt, text, candidates, comparisonKeys, selectedKey, evaluations}`。最大200候補・100評価・8MiB。候補の重複・不在の比較/採用キー・同一候補同士の比較・製品の不一致を拒否する。全体を検証した後でだけ復元し、音声は消して再生成する。未知のURL・数値ID等を話者情報へ取り込まない。旧レシピとの変換や、旧推薦評価の集計への取り込みは行わない。

各評価は両候補の製品・ネイティブ調声値・生成情報、採用結果、理由、セリフ、4軸と適用済み設定のコピーを持つ。AivisSpeechの順位・適合率・ライセンス許諾を生成しない。生成情報は完全なモデル版・ハッシュを含まない。ブラウザーの待機中止でサーバー側の生成は取り消せない。

## 製品比較履歴の集計と採用声の再利用

`shared/casting-dataset.ts`は`voice-atlas-casting` v1の評価履歴抽出と、専用集計形式`{format: "voice-atlas-casting-evaluations", version: 1, createdAt, records}`の検証・重複排除・検索/絞り込み・CSV出力・比較再開状態の検証を担当する。集計ではセッションの現在の候補は取り込まず、履歴だけを検証する。`historicalCastingCandidateSchema`は製品と数値の整合性を検証するが、現在のカタログの存在を要求しない。試聴/セッション復元/再開で使う`castingCandidateSchema`はVOICEVOXのカタログ照合を維持する。

重複キーはスキーマで整形した評価全体を用い、評価日時・生成情報の日時をUTC表記へ、AivisSpeechのUUIDを小文字へ正規化する。候補のA/B順・名前・製品別調声値・セリフ・理由・結果・4軸・設定・生成情報はキーに含む。最初の記録の値を保持し、条件や版が異なる記録、情報のない記録を統合しない。最大1000件、一回20ファイル・各32MiB・合計64MiB。全ファイルと重複後の件数を検証してからだけ状態を更新する。

`CastingEvaluationWorkbench`は製品比較欄の中に独立したメモリー状態を持ち、閉じても保持する。現在の履歴は明示的に追加し、自動同期しない。25件ずつ表示し、JSONは全体、CSVは絞り込み結果全体を出す。CSVはUTF-8 BOM・CRLF・引用符のエスケープ・テキストセルの数式解釈防止を適用する。製品別の採用件数は同程度/判断不可を除き、推薦品質のスコアや順位は計算しない。集計操作で試聴APIを呼ばず、現在の比較・音声を変更しない。

「この採用声で比較を再開」は、採用結果がA/Bであること、両候補の現行カタログ整合性、候補200件の上限をすべて確認してから、現在の2候補の設定と共通セリフ・保存対象を更新する。ほかの候補設定・現在の評価履歴・集計記録は保持し、音声は破棄して再生成する。AivisSpeechのUUID/スタイルは復元可能でも実際の生成時にエンジンへ再照合する。現在のカタログから外れたVOICEVOXを含む記録は、履歴を残したまま再開を拒否する。

再開した4軸と設定を`comparisonContext`として保持し、次の評価で現在の入力側の設定と取り違えない。親の入力状態は変更せず、明示的な操作で現在の声の方向へ戻せる。比較セッションv1に任意の`comparisonContext`を追加して保存/復元し、従来のv1で項目がなければ従来どおり現在の入力側の設定を使う。評価の取り込みは過去の設定を補完しない。

## AivisSpeechのモデル情報と利用条件

`GET /api/casting/aivis-models`はサーバーに設定したループバックの`GET /aivm_models`だけを呼ぶ。一次資料は[公式モデル情報ルーター](https://github.com/Aivis-Project/AivisSpeech-Engine/blob/master/voicevox_engine/app/routers/aivm_models.py)と[AIVMマニフェスト定義](https://github.com/Aivis-Project/aivmlib/blob/master/aivmlib/schemas/aivm_manifest.py)。マニフェストのモデルUUID・名前・版・説明・制作者・ライセンス本文と、話者UUID/スタイル名を取り込む。専用のクレジット指示欄や公式サイト欄を仮定せず、本文と制作者の記載から取得できるリンクを別に表示する。

このAPIは画像・音声サンプルを含む場合があるため、受信は2.5秒・8MiBまでとし、ローカルファイルパス・メディア等を除外する。モデルUUIDの辞書キー/本文の一致を確認し、同じ話者UUIDとスタイルを複数モデルで検出した場合はその関連付けを使わない。最大200件、各確認情報のUTF-8 JSONは4KiBまで。同時に実行中の確認要求だけを共有し、完了結果をサーバーでキャッシュしない。失敗・不正応答・未対応API・上限超過時は情報未取得として返し、通常の話者照合・生成は止めない。

`shared/aivis-model-info.ts`のスキーマで取得元の固定パス・確認日時・モデル/話者識別情報・文章・HTTP/HTTPSリンクを検証する。URLは認証情報・制御文字・非HTTPスキームを拒否し、サーバーからリンク先を取得しない。Reactのテキスト表示のみを使い、Markdown/HTMLを実行しない。ライセンスは記載あり/未記載/上限のため未掲載を区別し、上限超過時は切り詰めた本文を保存しない。モデルの利用許諾を真偽値で推定しない。

候補の任意の`modelInfo`は、AivisSpeechの話者UUID/スタイルと一致する場合だけ受け入れる。比較セッションv1と評価集計v1に追加し、旧データで項目がなければ補完しない。モデル情報を含む製品比較セッションの読み込みは8MiB、旧レシピは4MiB、集計ファイルは32MiB/一回64MiBのまま。評価の重複キーには確認情報全体を含め、確認日時とUUIDの表記だけ正規化する。情報のない評価や、内容が異なる評価を統合しない。CSVにも両候補のモデル情報を出力する。

`CastingWorkspace`は現在取得した情報と保存済みの情報を分ける。確認日時だけの違いでは変更扱いにせず、版・条件などの内容の違いを示す。音声キャッシュのキーは話者・セリフ・製品別調声値で、確認情報の再取得では無効化しない。生成要求時に確認できていた情報を音声に保持し、評価にはその音声の情報をコピーする。候補単位の明示的な再生成はキャッシュを使わず、成功時に作業中の候補の確認情報を更新できる。過去の評価は変更しない。情報は生成モデルのハッシュ等を含む完全な再現条件ではない。

## 実装の境界と性能

- `server/tts/aivis.ts`：AivisSpeech固有の検証クライアント。製品横断比較と`npm run probe:aivis`から導入済み話者の取得と生成を行う。[検証手順・仕様差・統合計画](aivis-spike.md)。
- `server/tts/index.ts`：TTS Adapterの契約とエンジン選択。対応する調声項目・話者一覧・音声と生成時の版情報を返す合成処理を持つ。接続確認と試聴APIは同じ選択処理を使う。未対応製品は通信前に拒否する。
- `server/tts/voicevox.ts`：VOICEVOX固有の話者スキーマ・スタイル解決・音声クエリ・WAV検証・任意の版取得。Adapter自身も文章とレシピを検証し、別エンジンの話者を拒否する。生成失敗後は版取得を行わない。版取得失敗は生成済み音声を失敗にしない。
- 現在のレシピと版情報はVOICEVOX用。第二エンジンの追加時は単位・範囲の確認、製品固有のレシピ型と保存形式・評価情報の拡張が必要で、既存の数値をそのまま流用しない。今回の分離だけでは第二エンジンの試聴は提供しない。
- `server/remote.ts`：外部通信のタイムアウト、リダイレクト拒否、応答サイズ上限、エラーの秘匿を共通化。
- `server/validation.ts`：リクエストスキーマをルート定義から分離。
- `server/analysis-schemas.ts`：プロバイダー向けスキーマを起動時に一度だけ生成。応答は毎回元のZodスキーマで検証。
- `src/components/`：調声コントロール、ツールチップ、話者マーク。`src/lib/http.ts`：JSON通信・ダウンロード。
- 接続確認は同じアプリへの実行中の要求だけを共有し、完了結果はキャッシュしない。再確認時に接続状態を再取得する。
- `GET /api/capabilities`の`voicevox`に`availableVoiceIds`（現在のカタログにある試聴可能な候補ID）と`checkedAt`（接続確認完了時刻）を返す。一回の`/speakers`応答をカタログ全体と照合し、空の正常応答は接続済み・試聴可能0件、不正応答や接続失敗は未接続・空配列とする。生の話者一覧やエンジンの数値IDは返さない。
- `shared/voicevox.ts`で事前照合と生成時の照合を共通化する。話者名・スタイル名を完全一致で照合し、スタイルの`type`が省略または`talk`の場合だけ試聴対象にする。生成時も一覧を取得し直して数値IDを解決し、事前確認の結果だけには依存しない。
- UIは確認中の生成を止め、確認要求の失敗時には古い接続情報を破棄する。再確認が重なった場合は最新の要求だけを反映する。状態表示と「試聴可能のみ」は接続確認時点の結果で、推薦式やスコアは変更しない。この表示条件はブラウザーの状態だけに置き、レシピの保存対象にせず、復元時に解除する。比較の選択中候補とその設定は、利用可否や表示条件の変更で置き換えない。
- 本番のハッシュ付き `/assets` のみ1年間のimmutableキャッシュ。HTMLは再検証し、APIはno-store。

## 入出力

| API                     | 内容                                                       |
| ----------------------- | ---------------------------------------------------------- |
| `GET /api/health`       | アプリの死活確認                                           |
| `GET /api/catalog`      | 話者カタログと確認日                                       |
| `GET /api/capabilities` | ローカルサービス・APIキー設定の状態                        |
| `POST /api/recommend`   | `{profile, preferences}` → カタログ候補                    |
| `POST /api/analyze`     | `{provider, image, direction, consent}` → 構造化した演出案 |
| `POST /api/preview`     | `{voiceId, text, recipe}` → WAV                            |

画像はData URLで受け、サーバーで最大8MB・25メガピクセルまで検証。向き補正・最大1536辺へ縮小・JPEG化を行い、Ollama・Anthropic Claude・Geminiにはbase64、OpenAIにはJPEG Data URLとして送信する。ファイル・DB保存は行わない。解析APIのJSON本文上限は12MiB、その他は16KiBで、入力圧縮は拒否する。外部JSON応答は2MiB、WAVは20MiBまで。本文の受信中もタイムアウトを適用する。

重い解析・音声合成はサーバーごとに同時1件とし、タイムアウトを設ける。別タブなどから競合した場合はHTTP 429で返す。サーバー側の処理はブラウザーの中止だけでは取り消せない。

## Claude接続

`ANTHROPIC_API_KEY`・`ANTHROPIC_MODEL` をサーバー側で読み、`provider: "anthropic"` を `POST /api/analyze` で受け付ける。キーはブラウザーへ返さない。外部AIへの送信同意はOpenAI・Claudeの切替時にリセットし、APIでも同意を必須とする。

Messages APIの `output_config.format` には対応範囲のJSONスキーマを渡し、数値・文字数などの制約は説明へ移す。応答は元のZodスキーマで再検証する。拒否・出力上限・不正応答では提案を作らずエラーを返す。

## Gemini接続

`GEMINI_API_KEY`・`GEMINI_MODEL` をサーバー側で読み、`provider: "gemini"` を受け付ける。Googleへの送信同意をAPIでも必須とし、`x-goog-api-key` ヘッダーで認証する。キーはURLに含めない。

`generateContent` へ `inlineData` のJPEGと補足を送り、`generationConfig.responseFormat` でJSON出力を指定する。送信用スキーマでは文字数制約を説明へ移し、応答は元のZodスキーマで検証する。完了した一つの候補のテキストだけを読み、思考ブロックは除外する。ブロック・未完了・不正応答はエラーにする。

## CI

`npm run check` はユニット/APIテストと、型検査を含む本番ビルドを実行する。型検査を重複実行しない。単独の `npm run typecheck` も利用可能。

GitHub ActionsはmainへのpushとPull Requestで実行し、同じrefの古い実行はキャンセルする。npmキャッシュを使い、インストール時の監査通信は省く。監査は必要時に `npm audit --audit-level=high` で実行する。整形検査もCIで実施する。

ブラウザーテストはChromiumのデスクトップ・モバイルの2構成を維持し、CIのワーカー数は2。実行に使うheadless shellだけを `npx playwright install --with-deps --only-shell chromium` でインストールする。[Playwright公式のブラウザー設定](https://playwright.dev/docs/browsers)に沿い、不要なフルブラウザーの取得を省く。ブラウザーキャッシュは[公式CIガイド](https://playwright.dev/docs/ci)が推奨していないため追加しない。

実際のGitHubランナーでの所要時間の短縮率は未計測。

## キャスティング表

`shared/casting-board.ts` は作品・キャラクター・使用場面の組み合わせを一意とする確定設定を定義する。`voice-atlas-casting-board` v1 JSONと専用localStorageキーで既存ライブラリ・比較JSONから分離し、最大100件・8MiBに制限する。比較記録全体を検証してコピーするため、後の元登録・履歴変更に依存しない。UUID・組み合わせの重複、不正な選択ID、生成情報の製品不一致もスキーマで拒否する。

`CastingBoard` は設定比較履歴から登録し、同じ組み合わせへの変更には明示的な置き換え確認を表示する。JSON読み込みは追加方式で、競合・容量超過・保存失敗時は一部を適用しない。ブラウザ保存に成功してから画面状態を更新する。候補への読み込みはコピーした設定と比較時のセリフを既存のライブラリ読み込み経路に渡す。生成・モデル情報は比較試聴時の情報を使い、元登録の古い情報で補わない。読み込み自体では音声生成を行わず、現在の話者の可用性・カタログ検証を維持する。
